## Rust: Clippy's `wildcard_enum_match_arm` catches `_ =>` on an enum, and not on a `(state, event)` tuple

*Idioms and antipatterns*

**Did you know**

A transition function written as `match (current_call_state, incoming_call_event)` usually ends with a catch-all such as `(unchanged_call_state, _) => unchanged_call_state`. Add a state, `OnHold`, and it compiles with no warning: `apply_call_event(OnHold, Answer)` quietly returns `OnHold`. Clippy has a lint for exactly this, `wildcard_enum_match_arm` ("wildcard match will also match any future added variants"), and it is in the opt-in restriction group. Measured with Clippy 0.1.99: it fires on `match current_call_state { CallState::Connected => true, _ => false }` and stays silent on the tuple match, whether the catch-all is `(unchanged_call_state, _)`, `(_, _)` or `_`.

**Show me**

```rust
// rustc 1.99.1 and Clippy 0.1.99, edition 2024, Debian. An illustrative call state machine.
#[derive(Debug, Clone, Copy)]
enum CallState { Idle, Ringing, Connected, OnHold } // OnHold is the state added later
#[derive(Debug, Clone, Copy)]
enum CallEvent { Answer, Join, HangUp }

fn apply_call_event(current_call_state: CallState, incoming_call_event: CallEvent) -> CallState {
    match (current_call_state, incoming_call_event) {
        (CallState::Ringing, CallEvent::Answer) => CallState::Connected,
        (_, CallEvent::HangUp) => CallState::Idle,
        (unchanged_call_state, _) => unchanged_call_state, // swallows OnHold; -W clippy::wildcard_enum_match_arm says nothing
    }
}

fn opens_audio(current_call_state: CallState) -> bool {
    match current_call_state {
        CallState::Connected => true,
        _ => false, // here the same lint fires: "wildcard match will also match any future added variants"
    }
}

fn main() {
    println!("{:?} {}", apply_call_event(CallState::OnHold, CallEvent::Answer), opens_audio(CallState::OnHold)); // OnHold false
}
```

**Why it matters**

The pair is where a state machine's rules live, and it is the one place the lint cannot see into: the scrutinee is a tuple, not an enum. Writing the pairs out instead is what brings the compiler back: without a catch-all, rustc refuses the match with `E0004` and names the missing pairs. In a table where every other pair was already written out, adding `OnHold` gave `E0004: non-exhaustive patterns: (CallState::OnHold, CallEvent::Answer) and (CallState::OnHold, CallEvent::Join) not covered`.

**Chew on this**

How many of your transition functions end in a catch-all that keeps the old state, and what would each one do with a state added next quarter? Is writing every pair out worth it at 4 states and 3 events, and at 20 and 15?

**Sources**

- https://rust-lang.github.io/rust-clippy/master/index.html#wildcard_enum_match_arm
- https://doc.rust-lang.org/reference/expressions/match-expr.html

**Verified**

Run in `rust:1-trixie` (Debian), rustc 1.99.1; Clippy 0.1.99 was added to a throwaway container with `rustup component add clippy` and run with `-W clippy::wildcard_enum_match_arm` (plus `-W clippy::pedantic`, which added nothing on the tuple). rustc also warns that `Ringing`, `Join` and `HangUp` are never constructed, because `main` builds only two values.

**Gotchas**

- A handler that matches the event alone, `match incoming_call_event { Answer | Join => true, HangUp => false }`, is exhaustive and gets no warning, and it returns `true` for `Join` in every state, because it never looks at one.
- `E0004` names at most three missing pairs: deleting the catch-all from the snippet above gave `(CallState::Idle, CallEvent::Answer)`, `(CallState::Idle, CallEvent::Join)`, `(CallState::Connected, CallEvent::Answer)` "and 3 more not covered", so the full list takes more than one build.

## C++: `default:` turns off `-Wswitch` for the next state you add, and `-Wswitch-enum` is the warning that ignores the `default`

*Idioms and antipatterns*

**Did you know**

`-Wswitch`, which `-Wall` enables, warns when a `switch` over an enum misses an enumerator, but only when the `switch` has no `default:`. Add `OnHold` to a `switch (state)` that ends in `default: return state;` and GCC 16.2 and Debian clang 19.1.7 both stay silent; the new state takes the `default` path. `-Wswitch-enum`, which neither `-Wall` nor `-Wextra` enables, warns about every unlisted enumerator even when a `default` exists: "enumeration value 'OnHold' not handled in switch" on GCC, "enumeration values 'Idle' and 'OnHold' not explicitly handled in switch" on clang. GCC's `-Wswitch-default` pulls the other way and asks for a `default` in the `switch` that has none.

**Show me**

```cpp
// C++23, g++ 16.2 and clang++ 19.1.7, Debian. An illustrative call state machine.
#include <cstdio>
enum class CallState { Idle, Ringing, Connected, OnHold }; // OnHold added later
enum class CallEvent { Answer, Join, HangUp };

CallState apply_call_event(const CallState const_current_call_state, const CallEvent const_incoming_call_event) {
    switch (const_current_call_state) {
    case CallState::Ringing:
        return const_incoming_call_event == CallEvent::Answer ? CallState::Connected : const_current_call_state;
    case CallState::Connected:
        return const_incoming_call_event == CallEvent::HangUp ? CallState::Idle : const_current_call_state;
    default:
        return const_current_call_state; // Idle, and now OnHold: -Wall -Wextra say nothing, -Wswitch-enum warns
    }
}

CallState apply_call_event_without_default(const CallState const_current_call_state, const CallEvent const_incoming_call_event) {
    switch (const_current_call_state) { // -Wswitch (in -Wall): enumeration value 'OnHold' not handled in switch
    case CallState::Idle: return const_current_call_state;
    case CallState::Ringing: return const_incoming_call_event == CallEvent::Answer ? CallState::Connected : const_current_call_state;
    case CallState::Connected: return const_incoming_call_event == CallEvent::HangUp ? CallState::Idle : const_current_call_state;
    }
    return const_current_call_state;
}

int main() {
    std::printf("%d %d\n", static_cast<int>(apply_call_event(CallState::OnHold, CallEvent::Answer)),
                static_cast<int>(apply_call_event_without_default(CallState::OnHold, CallEvent::Answer))); // 3 3
}
```

**Why it matters**

A `default:` is usually added for safety, so that an unexpected value does something defined. On an enum it also says "every enumerator I did not list is handled", and the compiler takes that at its word for every enumerator added afterwards. `-Wswitch-enum` is the flag that keeps asking, at the cost of listing the enumerators you meant to send to the `default`.

**Chew on this**

Which of your state `switch` statements have a `default`, and which of those would you want to hear about when an enumerator is added? Would `-Wswitch-enum` across your codebase be a warning you fix or one you turn off?

**Sources**

- https://gcc.gnu.org/onlinedocs/gcc/Warning-Options.html (`-Wswitch`, `-Wswitch-enum`, `-Wswitch-default`)
- https://clang.llvm.org/docs/DiagnosticsReference.html#wswitch-enum

**Verified**

GCC 16.2.0 (`gcc:latest`) and Debian clang 19.1.7 (`debian:stable` plus `apt-get install clang`), both Debian, `-std=c++23`.

**Gotchas**

- `-Wswitch-enum` also reports enumerators that the `default` handles on purpose: on the first `switch` above it named `Idle` as well as `OnHold`, so turning it on means listing those cases explicitly.
- clang's `-Wcovered-switch-default` added nothing on this file: it warns about a `default` in a `switch` that already lists every enumerator, which `apply_call_event` does not.

## F#: a match on the event alone is complete and never looks at the state, and the pair match's `FS0025` names only one missing pair

*Type system deep cuts*

**Did you know**

`match incoming_call_event with | Answer | Join -> true | HangUp -> false` is exhaustive, so F# gives no warning, and it decides what an event does in every state at once, because the state is not in the pattern. Match the pair, `match current_call_state, incoming_call_event with`, leave out the catch-all, and adding `OnHold` gets `FS0025`, but the message gives one example: "the value '(OnHold,Answer)' may indicate a case not covered", where rustc named both missing pairs for an equivalent table. Measured on .NET SDK 10.0.403, FSharp.Core 10.1.0.0, .NET 10.0.14.

**Show me**

```fsharp
// F# 10, FSharp.Core 10.1.0.0, .NET 10.0.14. An illustrative call state machine.
type CallState = Idle | Ringing | Connected | OnHold   // OnHold added later
type CallEvent = Answer | Join | HangUp

// Complete, no warning, and blind to the state.
let opens_audio (incoming_call_event: CallEvent) : bool =
    match incoming_call_event with
    | Answer | Join -> true
    | HangUp -> false

// The pair, without a catch-all.
let apply_call_event (current_call_state: CallState) (incoming_call_event: CallEvent) : CallState =
    match current_call_state, incoming_call_event with              // FS0025: the value '(OnHold,Answer)' may indicate a case not covered
    | Ringing, Answer -> Connected
    | Ringing, Join -> Ringing
    | Connected, Join -> Connected
    | (Idle | Connected), Answer -> current_call_state
    | Idle, Join -> current_call_state
    | _, HangUp -> Idle

printfn "%b %A" (opens_audio Join) (apply_call_event Ringing Join)   // true Ringing
```

**Why it matters**

The state machine's rules are in the pairs, and a match that leaves the state out of its pattern has no pairs to check. When the pair match does warn, it shows one example, so finding the next missing pair takes another build.

**Chew on this**

Which of your event handlers take the event and not the state? If you moved the state into the pattern, how many arms would each one need?

**Sources**

- https://learn.microsoft.com/en-us/dotnet/fsharp/language-reference/pattern-matching
- https://github.com/dotnet/fsharp/blob/main/src/Compiler/FSStrings.resx (the FS0025 text)

**Verified**

Run with `dotnet fsi` in `mcr.microsoft.com/dotnet/sdk:10.0`, which is Ubuntu 24.04 rather than Debian.

**Gotchas**

- `| _, HangUp -> Idle` covers `OnHold` for `HangUp` already, which is why the warning names `(OnHold,Answer)` and never `(OnHold,HangUp)`: a wildcard in one position is still a decision about the new state.
- A `Map<CallState * CallEvent, CallState>` used as the table has no such check: `Map.tryFind (OnHold, Answer)` returned `None` and `Map.find` threw `KeyNotFoundException` at runtime.

## TypeScript: a complete `` Record<`${State}:${Event}`, State> `` names every pair a new state needs, and `Partial` with `?? state` turns all of them into "stay put"

*Type system deep cuts*

**Did you know**

A template literal type turns the pair into a key: `` type Transition = `${CallState}:${CallEvent}` `` is every combination, twelve once `on_hold` exists. A table typed `Record<Transition, CallState>` must list all of them, so adding `on_hold` fails with `TS2739`, which names the three new keys: `"on_hold:answer", "on_hold:hang_up", "on_hold:join"`. Type the same table `Partial<Record<Transition, CallState>>` and look it up with `?? state`, a common way to avoid writing nine rows, and the new state compiles and stays put on every event. Measured on tsc 7.0.2, Node 26.13.0.

**Show me**

```ts
// TypeScript, tsc 7.0.2 --strict, Node 26.13.0. An illustrative call state machine.
type CallState = "idle" | "ringing" | "connected" | "on_hold" // on_hold added later
type CallEvent = "answer" | "join" | "hang_up"
type Transition = `${CallState}:${CallEvent}`

// Partial table plus a fallback: on_hold compiles and silently stays put.
const const_partial_transition_table: Partial<Record<Transition, CallState>> = {
    "ringing:answer": "connected",
    "connected:hang_up": "idle",
}
const const_apply_call_event_partial_table = (current_call_state: CallState, incoming_call_event: CallEvent): CallState => const_partial_transition_table[`${current_call_state}:${incoming_call_event}`] ?? current_call_state

// Complete table: TS2739, missing "on_hold:answer", "on_hold:hang_up", "on_hold:join".
const const_full_transition_table: Record<Transition, CallState> = {
    "idle:answer": "idle", "idle:join": "idle", "idle:hang_up": "idle",
    "ringing:answer": "connected", "ringing:join": "ringing", "ringing:hang_up": "idle",
    "connected:answer": "connected", "connected:join": "connected", "connected:hang_up": "idle",
}
const const_apply_call_event_full_table = (current_call_state: CallState, incoming_call_event: CallEvent): CallState => const_full_transition_table[`${current_call_state}:${incoming_call_event}`]

console.log(const_apply_call_event_partial_table("on_hold", "answer"), const_apply_call_event_full_table("ringing", "join")) // on_hold ringing
```

**Why it matters**

`Partial` plus a fallback is the TypeScript form of the catch-all arm in the Rust and C++ tips: it is written once, for convenience, and then answers for every state added later. The complete table costs a row per pair, and in exchange the compiler's error is the list of decisions the new state needs.

**Chew on this**

Which of your lookup tables are `Partial` because writing every key felt like noise? For which of them is "no entry" a decision someone actually made?

**Sources**

- https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html
- https://www.typescriptlang.org/docs/handbook/utility-types.html#recordkeys-type

**Verified**

Run in `node:lts-trixie` (Debian), Node 26.13.0, tsc 7.0.2 via `npx`; the emitted JavaScript printed `on_hold ringing` (emitted despite the TS2739 error, with `--noEmitOnError false`).

**Gotchas**

- The template key is checked only where it is written inline: `` const_full_transition_table[`${current_call_state}:${incoming_call_event}`] `` compiled, but `` const const_bound_transition_key = `${current_call_state}:${incoming_call_event}` `` widened to `string`, and `const_full_transition_table[const_bound_transition_key]` failed with `TS7053`. Adding `as const` to the binding kept the union and compiled.
- The complete table makes `const_apply_call_event_full_table` return `CallState` with no `undefined`, because every key is present; with `Partial`, the lookup is `CallState | undefined`, which is what invites the `?? current_call_state`.

# The functional angle: a transition table as a value refuses a missing row in Rust and TypeScript, fills it with the first state in C++, and finds out at runtime in F#

Draws on all four tips. Each tip's catch-all is a function deciding the missing case for you. The alternative is to make the table a value whose type knows how many rows it must have, and then see which languages hold the value to that.

```rust
// Rust: a const array; its length is part of the type.
#[derive(Debug, Clone, Copy)]
enum CallState { Idle, Ringing, Connected, OnHold }
const CALL_STATE_COUNT: usize = 4;
const CALL_EVENT_COUNT: usize = 3;
const CALL_STATE_TRANSITIONS: [[CallState; CALL_EVENT_COUNT]; CALL_STATE_COUNT] = [
    [CallState::Idle, CallState::Idle, CallState::Idle],
    [CallState::Connected, CallState::Ringing, CallState::Idle],
    [CallState::Connected, CallState::Connected, CallState::Idle],
]; // error[E0308]: expected an array with a size of 4, found one with a size of 3
```

```cpp
// C++23: a constexpr std::array; a missing row is value-initialized.
#include <array>
#include <cstdio>
enum class CallState { Idle, Ringing, Connected, OnHold };
enum class CallEvent { Answer, Join, HangUp };
constexpr std::size_t CALL_STATE_COUNT = 4;
constexpr std::size_t CALL_EVENT_COUNT = 3;
constexpr std::array<std::array<CallState, CALL_EVENT_COUNT>, CALL_STATE_COUNT> CALL_STATE_TRANSITIONS{{
    {CallState::Idle, CallState::Idle, CallState::Idle},           // Idle
    {CallState::Connected, CallState::Ringing, CallState::Idle},   // Ringing
    {CallState::Connected, CallState::Connected, CallState::Idle}, // Connected
}};                                                                // no OnHold row, no warning
int main() {
    const CallState const_next_call_state_after_answer = CALL_STATE_TRANSITIONS[static_cast<std::size_t>(CallState::OnHold)][static_cast<std::size_t>(CallEvent::Answer)];
    std::printf("%d\n", static_cast<int>(const_next_call_state_after_answer)); // 0: the missing row reads as Idle
}
```

```fsharp
// F#: a Map keyed by the pair; a missing key is found when it is looked up.
type CallState = Idle | Ringing | Connected | OnHold
type CallEvent = Answer | Join | HangUp
let call_state_transitions : Map<CallState * CallEvent, CallState> =
    Map.ofList [ (Ringing, Answer), Connected; (Ringing, Join), Ringing; (Connected, HangUp), Idle ]
printfn "%A" (Map.tryFind (OnHold, Answer) call_state_transitions)   // None
printfn "%A" (Map.find (OnHold, Answer) call_state_transitions)      // KeyNotFoundException
```

```ts
// TypeScript: the complete Record from the TypeScript tip above.
type CallState = "idle" | "ringing" | "connected" | "on_hold"
type CallEvent = "answer" | "join" | "hang_up"
const const_full_transition_table: Record<`${CallState}:${CallEvent}`, CallState> = {
    "idle:answer": "idle", "idle:join": "idle", "idle:hang_up": "idle",
    "ringing:answer": "connected", "ringing:join": "ringing", "ringing:hang_up": "idle",
    "connected:answer": "connected", "connected:join": "connected", "connected:hang_up": "idle",
} // TS2739: missing "on_hold:answer", "on_hold:hang_up", "on_hold:join"
```

Each was run: Rust on rustc 1.99.1, C++ on GCC 16.2 and Debian clang 19.1.7 (`-std=c++23 -Wall -Wextra`, GCC also with `-Wmissing-field-initializers`, no warnings), F# on .NET SDK 10.0.403, TypeScript on tsc 7.0.2, with the results in the comments.

| Language | Table as a value | A row missing for the new state | What it costs |
| --- | --- | --- | --- |
| F# | `Map<CallState * CallEvent, CallState>` | `None` from `tryFind`, `KeyNotFoundException` from `find`, at runtime | a tree lookup per step, and no compile-time count |
| Rust | `[[CallState; CALL_EVENT_COUNT]; CALL_STATE_COUNT]` | `E0308` at compile time | `CALL_STATE_COUNT` is written by hand, so it must be bumped with the enum |
| C++ | `std::array<std::array<..>, CALL_STATE_COUNT>` | compiles; the row reads as the first enumerator, `Idle` | the same hand-written count, and aggregate initialization fills the gap silently |
| TypeScript | `` Record<`${State}:${Event}`, State> `` | `TS2739` naming each missing key | one entry per pair, written out |

F# is the baseline because its standard table, `Map`, is the one with no size in its type, which puts the cost of the functional shape in plain view: a value is only as checked as its type. Rust and C++ both carry a count, and only Rust refuses a short initializer.

When your next state arrives, which of your tables will tell you it is missing a row, and which will answer for it?

# The security angle: an event should not be callable in a state where it is not allowed

Draws on all four tips, and runs in both directions: the tips show catch-alls and event-only handlers that the languages accept, and Rust's type system can make the illegal call impossible to write. Apple's fix was "improved state management"; the insecure shape below is the class, not FaceTime's code.

```ts
// TypeScript. Looks like a tidy, exhaustive event handler. It never asks what state the call is in.
type CallEvent = { kind: "answer" } | { kind: "join"; joiner_id: number } | { kind: "hang_up" }
const const_fn_audio_after = (incoming_call_event: CallEvent): "open" | "closed" => {
    switch (incoming_call_event.kind) {
        case "answer":
        case "join": return "open"   // opens audio in every state, because it never asks which one
        case "hang_up": return "closed"
    }
}
console.log(const_fn_audio_after({ kind: "join", joiner_id: 9 })) // open
```

It compiles under `--strict` with no error, and the `switch` is exhaustive. The constructive direction is to make each state its own type, so that the operation does not exist where it is not allowed:

```rust
// Rust: typestate. "Join" and "open audio" exist only on a connected call.
struct RingingCall { caller_id: u32 }
struct ConnectedCall { caller_id: u32 }
impl RingingCall {
    fn answer(self) -> ConnectedCall { ConnectedCall { caller_id: self.caller_id } } // consumes the ringing call
}
impl ConnectedCall {
    fn join(&mut self, joiner_id: u32) { println!("call {} joined by {joiner_id}", self.caller_id); }
    fn open_audio(&self) { println!("audio open for {}", self.caller_id); }
}
fn main() {
    let ringing_call = RingingCall { caller_id: 7 };
    let second_caller_id: u32 = 9;
    ringing_call.join(second_caller_id); // error[E0599]: no method named `join` found for struct `RingingCall`
}
```

The classes, in this part's classification: [CWE-841](https://cwe.mitre.org/data/definitions/841.html), Improper Enforcement of Behavioral Workflow, and [CWE-372](https://cwe.mitre.org/data/definitions/372.html), Incomplete Internal State Distinction. NVD records no CWE for CVE-2019-6223.

| Language | What goes wrong | What the language does | Still on you |
| --- | --- | --- | --- |
| Rust | a tuple catch-all swallows a new state | `E0004` without the catch-all; typestate makes the call `E0599` | no `_` on the pair; one type per state where an event must be refused |
| C++ | `default:` takes the new enumerator | `-Wswitch` only without a `default`; `-Wswitch-enum` even with one | turn on `-Wswitch-enum`; give each state its own type for the dangerous operations |
| F# | an event-only match is complete | `FS0025` on the pair match, one example at a time | put the state in the pattern |
| TypeScript | an event-only `switch` opens audio in any state | a class per state with a literal `state` tag refuses `open_audio(ringing)` (TS2345) | an object literal `{ state: "connected", caller_id: 7 }` is still accepted, so the tag is not a credential |

Rust is the baseline because typestate turns "this event is not allowed in this state" into a missing method rather than a missing check. The TypeScript row was measured with `class RingingCall { readonly state = "ringing" as const ... }` and `class ConnectedCall { readonly state = "connected" as const ... }` on tsc 7.0.2; the Rust sample on rustc 1.99.1.
